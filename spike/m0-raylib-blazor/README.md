# M0 spike - Raylib-cs 7.0.2 + `raylib.a` in Blazor WebAssembly

Throwaway probe kept as evidence for [spike 0001](../../docs/spikes/0001-raylib-cs-blazor-wasm.md).
Nothing here is framework code; it is a single Razor component plus a JS module.

## What it proves

- a prebuilt Emscripten `raylib.a` (raylib 5.6-dev) links into a fresh Blazor WASM app;
- a canvas is bound to `Blazor.runtime.Module['canvas']` before `InitWindow`;
- `requestAnimationFrame` drives exactly one synchronous `[JSExport]` per frame;
- assets are fetched at boot and written into MEMFS, then loaded with `LoadTexture` / `LoadSound`;
- Fit-mode letterboxing plus `SetMouseScale(backing/css)` keeps the mouse exact at any CSS scale;
- a readable error overlay appears when boot fails.

## Run

```bash
dotnet workload install wasm-tools        # once per machine

# dev loop
dotnet run                                # http://localhost:5xxx

# release publish + static serve
dotnet publish -c Release -p:EmccLinkOptimizationFlag=-O0 -o ../../artifacts/m0
python3 -m http.server --directory ../../artifacts/m0/wwwroot 5099
```

`EmccLinkOptimizationFlag=-O0` is required on this toolchain: the `-O2` link runs a `wasm-opt` that rejects
`--enable-bulk-memory-opt` (Binaryen 117). See section 4.3 of the spike notes.

## Layout

| Path | Purpose |
|---|---|
| `M0Canvas.razor` / `.razor.cs` | The whole probe: boot, loop, 3D + 2D drawing, resize callback |
| `wwwroot/js/m0.js` | Canvas binding, asset preload into MEMFS, rAF loop, layout |
| `Assets/` | `logo.png` (64x64) and `blip.wav` (0.15 s 440 Hz) |
| `Raylib.props` | `NativeFileReference` for `raylib.a` and the Emscripten flags |
| `raylib.a` | Vendored native library, 1.6 MB, raylib 5.6-dev |
| `M0RaylibBlazor.csproj` | Host project; contains the asset sync target |

`wwwroot/assets/` is generated by the build (see the `SyncGameAssetsIntoWwwroot` target) and gitignored.
