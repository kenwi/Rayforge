# Spike 0006 - AOT in Release

- **Date:** 2026-10-22
- **Time spent:** ~1 h
- **Milestone:** M5
- **Verdict:** **OPT-IN, not default.** AOT builds and runs after one Raylib-cs workaround, but it is ~5x
  slower to build, ~2.8x larger raw (~2x brotli), and did not improve startup in the measured setup.
  `RunAOTCompilation` stays off; the framework makes the workaround automatic when a user opts in.

## 1. Question

PLAN.md says AOT is not part of v1 but must be measured in M5:

> What do build time, payload and runtime cost look like with `RunAOTCompilation=true`, and should Rayforge
> enable it by default or document it as opt-in?

## 2. Environment

| Component | Version |
|---|---|
| OS | Linux (Omarchy/Arch), x86_64 |
| .NET SDK | 10.0.402 |
| wasm-tools | 10.0.113 (Emscripten 3.1.56, Binaryen 117) |

| Browser | Chromium 154 headless, SwiftShader, 1280x720 |
| Game | HelloWorld (three assets, raylib 6.0, Raylib-cs 8.1.0) |

Commands (clean `obj/bin` for the non-AOT baseline; the AOT run reused the link cache after the first try):

```bash
dotnet publish games/HelloWorld/HelloWorld.Web -c Release -o /tmp/rayforge-noaot
dotnet publish games/HelloWorld/HelloWorld.Web -c Release -p:RunAOTCompilation=true -o /tmp/rayforge-aot
```

## 3. Failure: mono-aot-cross crashes on Raylib-cs

The first AOT publish fails while precompiling the generated bindings:

```text
[Raylib-cs.dll] ... mono-aot-cross ...
* Assertion at .../mono/sgen/sgen-alloc.c:409, condition `*p == NULL' not met
Precompiling failed for .../Raylib-cs.dll with exit code 1
```

`DisableParallelAot=true` and `AOTMode=LLVMOnly` do not help (`LLVMOnly` also rejects the SDK's
force-interpreted `Microsoft.JSInterop.WebAssembly`). The assembly is simply too large for this AOT compiler.

### Workaround

Keep Raylib-cs interpreted, using the same metadata the SDK uses for `Microsoft.JSInterop.WebAssembly`:

```xml
<_WasmAssembliesInternal Update="@(_WasmAssembliesInternal)" Condition="'%(Filename)' == 'Raylib-cs'">
  <AOT_InternalForceToInterpret>true</AOT_InternalForceToInterpret>
</_WasmAssembliesInternal>
```

This lives in `Rayforge.Web/buildTransitive/Rayforge.Web.targets` behind
`Condition="'$(RunAOTCompilation)' == 'true'"`, so in-repo games and package consumers get it automatically.
It uses SDK-internal item names; remove it when the AOT compiler can handle Raylib-cs.

## 4. Measurements

| Metric | No AOT (`-O0`) | AOT (`-O0`) | Ratio |
|---|---:|---:|---:|
| Publish wall time | **16 s** (clean) | **102 s** first / **84 s** warm | ~5-6x |
| Raw `wwwroot` | **6,633,481 B** (6.33 MiB) | **18,581,673 B** (17.72 MiB) | **2.80x** |
| Brotli siblings | **2,032,185 B** (1.94 MiB) | **4,024,738 B** (3.84 MiB) | **1.98x** |
| Files (raw) | **55** | **55** | 1.00x |
| `dotnet.native.*.wasm` | **2,491,188 B** (2.38 MiB) | **14,430,117 B** (13.76 MiB) | **5.79x** |
| Load → "Click to play" (median of 5) | **612 ms** | **669 ms** | 1.09x slower |
| Browser smoke | pass | pass | - |

Startup was measured locally against a static server with a fresh browser context per run; it includes
download, wasm compile and Blazor boot. AOT does not help here because Raylib-cs is interpreted and the
larger module costs compile time. A game with more managed hot code could still benefit at runtime; this
demo does not.

The browser smoke test (page loads, start button, non-blank canvas, animated frames, no console errors,
no failed requests) passes on the AOT publish, so the workaround does not break the runtime.

## 5. Decision

1. **Keep AOT off by default.** No `<RunAOTCompilation>` in framework props or hosts.
2. **Document the opt-in** (`-p:RunAOTCompilation=true`) and its costs in the deployment/build docs.
3. **Do not add an AOT job to CI.** It would add ~1.5 minutes and ~18 MB to every run for no proven benefit;
   the size budget already tracks the default publish.
4. **Keep the Raylib-cs force-interpret target** so opt-in works out of the box. It is conditioned on AOT and
   has no effect on normal builds.
5. Re-measure if (a) the AOT compiler can precompile Raylib-cs, (b) a real game shows managed-code hotspots,
   or (c) .NET changes the AOT payload/link model.
